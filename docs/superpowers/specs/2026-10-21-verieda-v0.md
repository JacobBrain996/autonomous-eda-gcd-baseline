# VeriEDA V0 design

The user authorizes autonomous architecture and local implementation. This is an architectural extension of the existing standard-library CLI. GCD timing closure is not a development prerequisite. No new cloud run or publication is authorized by this design.

Options: a deterministic CLI policy reuses existing evidence adapters with minimal cost; an LLM policy would add an external dependency before the action/verifier contract exists; a workflow orchestrator would add remote side effects before candidate acceptance is trustworthy. Choose the deterministic CLI and explicit proposal/evaluation separation. This is the first control policy, not a novelty claim or successful EDA optimization.

`case.py` builds a state from separately pinned Smoke and acceptance archives, not arbitrary agent JSON. A case profile binds design, tool/constraint identities, run identities and archive SHA256. Native inputs must equal the Smoke final inputs byte-for-byte. Report precise timing/path data and gaps. A manually reviewed proof may be reused only for its exact archive, proof/script hashes and reset contract, with review provenance explicit; generic reported success stays UNKNOWN. Never promote a claim from an unpinned bundle.

`policy.py` proposes typed, content-addressed candidates: audit constraints, timing-oriented synthesis mapping, or critical-cell sizing investigation. No RTL/SDC/flow changes are applied. Explain cell/net evidence, prioritize the dominant contribution, disclose missing dependencies, and distinguish legality of the proposed scope from execution readiness. Fixed identities and allowable parameter changes are part of each candidate. Wall-clock values are hard requested caps, not predicted duration/price. Zero budget, repeated failed/unknown candidates and missing evidence cause explicit stop/review decisions; history is tied to state and candidate hashes.

`adoption.py` independently compares loaded before/after states. Verify same frozen design/constraints/tools, distinct experiment evidence, real improvement, complete required gates, same proven contract and candidate scope. Negative timing/DRC/equivalence rejects; missing proof, unchanged constraints, coverage or execution evidence prevents acceptance. Policy scores cannot supply PASS. CLI never executes commands or a workflow from a candidate.

Commands: `plan` loads archives/profile, optional bounded history, and emits state + candidate manifest + audit decision as JSON; `evaluate` loads two profiles/archive pairs and emits the independent acceptance verdict. Exit zero means planning/evaluation completed; result verdict is separate. Malformed evidence/config exits 2. Source/inputs stay untouched; stdout can be saved by the caller.

Tests: pinned real archive integration, forged review/identity, cross-run netlist mismatch, incomplete timing paths, cell-vs-net policy, no budget, repeated failure, candidate mutation/illegal SDC, false acceptance, incompatible contracts, missing gates, distinct evidence and improvement. No synthesis/STA/proof is rerun.

Non-goals this increment: cloud execution adapter, automatic candidate application, timing closure, full SDC verification, Agent research efficacy or multi-design validation. The full project goal remains open after this increment.
