# Action result recovery and feedback

Extend the current CLI with bounded seal-action / inspect-action. Keep local execution only; no cloud/push authority. Reuse evidence.read_bundle/verify_bundle and immutable action packages. This is a results adapter, not a new execution platform.

Seal only the four package files, action-execution.json or launcher-result.json, effective.log, synth.log and fixed synthesis netlist/ODB paths. Reject links, bound per-file/aggregate bytes, create ZIP exclusively and checksum every payload. Never scan/export unrelated files or process environment. Inspector validates checksums, package/state/candidate binding, fixed step argv, actual rc/timeout/signal, log/output hashes and frozen source/tool fingerprint claims. Caller-supplied trusted ZIP SHA can anchor identity; self-consistent hashes alone do not authenticate a cloud job.

Return NOT_RUN / TIMEOUT / TOOL_SIGNAL / ERROR / UNKNOWN / SYNTHESIS_COMPLETED with explicit observations and missing checks. A successful synthesis remains unaccepted pending physical/formal/constraint validation. Generate a policy-compatible history record only with observed execution, validated receipt/log consistency and finite measured runtime; the record's provenance is separate. Never convert an unknown runtime to zero. Partial evidence remains HOLD and cannot create ACCEPTED. Historical package validation uses bound old source bytes, not silently the current executor's source hash.
